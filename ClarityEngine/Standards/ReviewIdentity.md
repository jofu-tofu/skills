# Review Identity and Delivery

ReadabilityGate owns this rule. Verify checks the evidence it produces; authoring, review and conversion callers use the same delivery check. A review applies to the content and reader assumptions it actually checked, not merely a filename or a previous Ready label.

## Freeze Each Round

Keep the artifact copy and an `inputs/` snapshot in each round. Snapshot the actual brief, audience question files and matching answer keys, contract when present, supplied source notes/files, and verification evidence. Record absent inputs as absent; do not invent sources or requirements to fill the snapshot. When audience, expertise, exposure or purpose changes, prepare questions and keys for that context before starting reviewers.

In `panel.md`, identify the artifact content and these input versions with hashes or another reproducible content comparison. Record each reviewer's exact permitted snapshot inputs and each verification layer's artifact/version and conditions. A snapshot preserves evidence; copying an old report into it does not make that report applicable. Do not give Readers the brief, keys, contract or other inputs their lens does not permit.

Keep snapshots unchanged from the moment they are frozen. Later rounds take new snapshots instead of overwriting the context an earlier result used. A report names its artifact identity and frozen review context so a caller can check their applicability.

## Reuse Applicable Evidence

The same content and assumptions at another path may reuse its review. Confirm content equality; a matching filename, audience name or status alone is insufficient. An unrelated later tool error does not erase established evidence.

After a change, identify what each affected check depended on. Wording changes require current meaning and reader checks for the changed content; changed audience assumptions require current audience-fit and Reader evidence with matching questions. Changed sources or contracts require reassessing dependent claims or constraints. Preserve evidence whose inputs and applicability are demonstrably unchanged, with the reason. Do not restart unrelated checks merely because a path or unrelated input changed, or treat missing evidence as a confirmed defect.

Verify records a current-evidence disposition for unresolved earlier Blockers and Majors. A declined repair or a new clean lens report does not by itself resolve their underlying concern; changed applicability or an earlier false diagnosis must also be explained from evidence.

File, rendered and target-app evidence must also match the delivered representation and applicable conditions. A text-equivalent conversion does not establish that a new file opens, renders or works in its destination. Follow FormatAdapters for those layers.

## Check Before Delivery

Compare the actual deliverable and current brief/contract/source assumptions with the report's frozen identity after all editing, including manual shortening, paragraph repairs and changes made outside the gate. Keep the original report as evidence for its original inputs.

If they differ, continue authorized work: refresh the affected inputs and perform the required current checks, then have Verify determine the applicable statuses. Existing edit scope, locks and repair limits still apply; this rule grants no extra editing authority or new repair rounds. When checks are unavailable or the repair limit is exhausted, deliver the useful artifact with the affected evidence explicitly unverified. Preserve confirmed current defects and unaffected results; never copy an earlier Ready/Pass to unchecked changed content or a different audience. Report a missing current Reader as NotVerified, not as a proved comprehension failure.

When content and context match, return the applicable report without a needless rerun. State which artifact and audience it covers and any remaining limits. This comparison is an execution step, not a request for routine user approval.
