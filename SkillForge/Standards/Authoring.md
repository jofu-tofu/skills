# Authoring guidance

Load when drafting instructions or changing routing, not for every evaluation.

- Keep the entry point short: purpose, user-intent routing, and concrete examples.
- Preserve the target's intent and explicitly discuss proposed changes to its purpose.
- Write direct instructions explaining important reasons; avoid unsupported universal claims about prompting.
- Separate user outcomes from reusable internal operations. Use references when needed, not mandatory chains for every edit.
- Name input, output, completion, and evidence limits for substantive workflows.
- Use the target platform's format. SkillForge's legacy validator checks its own naming conventions; those conventions are not universal skill quality.
- Use real near-miss prompts to check routing changes. Distinguish a good description from observed runtime selection.

For research integration, read [KnowledgeIntegration](KnowledgeIntegration.md). Extract a supported implication, record evidence limits, and integrate the rationale where it belongs. A research citation alone does not demonstrate that a revision helps.
