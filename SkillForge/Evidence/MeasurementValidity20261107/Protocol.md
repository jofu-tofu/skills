- Untested assumption: naming the three uses explicitly improves decisions beyond the existing scope prose. Baseline adequacy is a live alternative.
- Desired function: select useful revisions and reject unsupported claims. More instructions and completed fields are not benefits.

## Bounded skill-change comparison

Options: (A) unchanged scope prose; (B) a compact use-specific qualification section and template field; (C) mandatory typed schema/tool gate. Test B against A. C adds enforcement cost while still being unable to judge semantic truth; defer it unless a demonstrated consumer failure calls for it. No structural redesign or new runtime tool is required.

Freeze B only after fixed-artifact results. Run one separate model session per method on the same evidence packet, through EvaluateSkill and DesignMeasurement. Ask it to choose an actual historical repair for bounded source-validation use, produce an executable selection handoff, and assess three uses of the measure. Include preservation cases: a direct deterministic contract, unsupported factual truth, unresolved reference, and design-only measurement. Replay the selected real tool on independent outer cases. Expected decisions derive from the explicit request and executable evidence, not an unsupported model judge.

Benefit rule: retain B operationally only if it corrects a consequential baseline decision and preserves all mandatory controls. A tie retains A and preserves B as a rejected/unproven patch. A detected candidate defect permits one revised matched follow-up with a separately frozen amendment and fresh contrasts. A saturated tie stops identical repeats; a targeted scope boundary check may still resolve an uncovered risk. Do not claim model reliability from one pair.

Budget: 174 initial CLI observations plus scorer controls; two model sessions up to eight minutes each; at most one justified correction pair. No mandatory expensive calibration for deterministic contracts. Record actual latency/usage without general cost claims.
