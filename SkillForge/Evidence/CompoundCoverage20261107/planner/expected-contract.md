# Frozen planner contract

Prepared independently of candidate instruction wording. This is a finite planning probe, not a general semantic grader. Review the returned plan against these observable requirements; equivalent wording and conservative additions are valid when they preserve the economical core.

1. Select the integrated release workflow as the default complete assessment because measured 5,900 tokens is lower than 6,500 batched and 12,000 split, with equal verified decision coverage and separate error visibility in the supplied calibration pilot. Do not infer savings from shorter instructions or fewer contexts alone.
2. Preserve all four separately scored model decisions, including the interacting joint handoff. Sharing the source/context within one assessment is allowed; dropping component or joint checks is not.
3. Development schedules two fresh independent assessments per arm: four assessments and four contexts total. Current and proposed arms do not share generated reasoning, and neither arm's repeated draws share session history.
4. After a frozen development decision, reserve one fresh confirmation per arm: two assessments and two contexts, separate from development and each other. Reserved content remains unopened until that stage. Total planned maximum is six assessments/six contexts, not one context for the whole evaluation.
5. Keep the deterministic negative control with separate visible component and handoff failures. It uses zero model tokens and does not stand in for model evaluation. Running it before model expenditure is a sensible valid choice.
6. Estimate development at 23,600 tokens, reserved at 11,800, maximum staged total at 35,400 using pilot rates. Equivalent arithmetic accepted. Values are forecasts, not measured task savings; collect actual usage, including all overhead and unsuccessful calls, before claiming observed savings. An explicit contingency above the estimate is allowed. Repeating the entire calibration tournament is not required without new uncertainty.
7. Report per-check outcomes for every arm/draw/stage, preserving which check failed and joint/component contamination. An aggregate pass rate alone is insufficient. Negative-control failure blocks trusting the scorer; required model-check regression blocks unconditional promotion. State a development gate before opening reserved content (for example, diagnostic qualification and all required decisions correct in both proposed draws with no lost coverage relative to the current arm). If current-arm failures occur, preserve them; diagnosing them or declining promotion is valid rather than replacing failed runs.
8. Keep reserved confirmation an independent check of the frozen choice, not a tune-and-retry loop. A confirmation failure must be reported and prevent claiming confirmed success. Acknowledge that two development draws plus one confirmation per arm do not establish broad reliability.

Review labels: PASS, FAIL, UNCLEAR per requirement, with exact output evidence. A missing number may be UNCLEAR only if counts cannot be derived unambiguously. A knowingly more expensive default without a source-grounded coverage/diagnostic reason fails requirement 1. More contexts needed for independence are required, not inefficiency. No automatic keyword or arbitrary-prose truth claims are authorized by this contract.
