# Reassessment protocol — before candidate edits

Baseline `d98ff45173ae50e228cf76af403e99829b6e2f25` includes current integrated owner navigation plus this branch's comparative-resolution work. See Inventory.md for prior-session coverage and all candidate dispositions. Scope is a SkillForge retrospective and bounded revival of historically inconclusive ideas; no other skill change.

Selected mechanism: optional historical decision map, a simplification of the rejected ExperimentMemory candidate. No new mandatory procedure or model retrieval stage. It links real reports and conditions, separates original decision from later integration and preserves opposing evidence. Baseline keeps ordinary search and exactly the same source reports. Candidate preparation cost is reported separately; benefit cannot mean merely reading a shorter, unsupported summary.

Two fresh paired task contexts: (1) decide whether to make preselected lessons standard and allocate the next useful experiment; (2) decide whether the evidence supports an efficiency-based replacement of the process and which already-integrated components should be treated as pending. Prompts name the desired decision, not the historical reports, answers or distinctions. Source-grounded references are frozen before subjects; no grader key or outer protocol in method/history snapshots. Both start at the normal SkillForge entry point and use the same instrumented read/search/list tool. Candidate finds the optional map through the existing attempt index. No mid-run naming or exposure coaching.

History is a selected broader archive of real SkillForge reports/decisions, including failed/tied experiments, older contrary deployment advice and later integration records. It is not a fabricated maze or exhaustive archive. Preserve the same original relative structure in both arms. Case selection is diagnostic: known historical subject matter, not independent population sampling. Do not forbid baseline search or prior evidence; do not force different selected sources.

Measure benefit as successful returned UTF-8 text bytes and read/search/list invocations, subject to correct, source-supported actionable decisions and explicit uncertainty. Count method and history access together. Reuse the already qualified bounded-page reader, requalify accounting on the new snapshot, inspect truncation disclosures and logged returned text. Bytes are a context proxy, not billing, reasoning cost or latency. Include failure attempts separately. Same tool access, page cap and prompts in both arms; one command per output with sufficient tool-output budget. Raw ledgers remain external and hashed.

Frozen benefit rule: adopt the optional map only if both task pairs preserve every material reference constraint and actionable next decision, candidate uses fewer successful returned bytes in both pairs without more total reader invocations, and no unsupported provenance/status claim or maintenance regression occurs. Report absolute differences; do not infer general causality from one pair/task. Otherwise retain baseline or make one diagnosed feasible correction, preserving the initial results. Do not repeat saturated answers until a favorite wins. If the map is unused, report no exposure rather than force it into the prompt.

Qualification: source excerpts independently constrain judgments; positive/negative/valid-alternative/misleading shortcuts establish bounded grading behavior. Direct reader tests check emitted/logged bytes, page continuation and no hidden truncation; inspect actual read exposure. A fresh reviewer checks outcomes and caller decisions against source records after execution. This tests retrieval-based decisions, not improved downstream repairs. Broader semantic improvement would need a separate task.

Integration means incorporating a supported change into this same local branch, with provenance and changed-link checks. Whole old candidate snapshots will not overwrite newer protections. Other candidates receive explicit already-integrated/superseded/not-informative/active-owner dispositions; unexecuted hypotheses are not marked successful. Completion requires inventory, executed selected comparison, source-grounded decisions, retention/rejection and preservation evidence. A justified no-change result is allowed; installation/push remain outside scope.
