# Historical candidates: measured tradeoffs, baseline retained

Reviewed 13 SkillForge candidate families from Nov 3–7 using selected turns in three actual chats and saved reports. This is a selected historical review, not every session or other skill. [Inventory](Inventory.md) separates already integrated changes, superseded mechanisms, genuinely unresolved ideas and active work owned elsewhere. No new runtime change from this reassessment met the frozen adoption rule. The earlier tie-diagnosis changes and integrated owner navigation remain on the same branch.

## What deserved another trial

The rejected historical-evidence map had tied answers, cued exposure and unmeasured reading cost. A simpler optional map offered a genuinely different test: useful source-grounded decisions over a broader real archive, with returned reading volume measured. Mandatory similarity/outcome selection still had no meaningful contrast because both delivered the same packet; rerunning that unchanged would not identify a selector advantage. Old generation, activation, compact-workflow and preflight ideas were already integrated. The separate workflow-efficiency follow-up completed during this review and rejected its own candidates on measured costs; it was not rerun here.

Baseline `d98ff45` includes current main's owner navigation and this branch's tie guidance. V1 adds only an optional decision map and index link. V2 uses the single allowed correction: an optional link in the existing SKILL Status navigation. All task text, source archive, decision criteria and adoption thresholds remain unchanged. Eight fresh reader sessions completed: two tasks, two arms, two versions. No other skill was modified.

This was not current-run answer leakage, but prevents claiming clean discovery without answer-like guidance. It does not rescue the candidate's independent T1 cost failure.

## Disposition

The frozen rule required correct, supported decisions and fewer returned bytes in **both** tasks without more total calls. V1 failed decision/exposure requirements; V2 failed the cost requirement. Reject both and stop after the allowed correction. Restored SKILL.md and Improvements/Index.md to the baseline before adding only this historical result entry; removed DecisionHistory.md. Existing procedure changes from the earlier tie-diagnosis task remain intact. No main merge, push or installation occurred.

The conditional release-status result remains a candidate lead, not an adopted efficiency claim. A future status-only lookup would need a new scoped contract and fresh tasks, excluding answer artifacts from broad search and retaining ordinary access to primary records. Do not infer that historical reuse never helps, or repeat these same tasks until a preferred version passes. No such further trial is required to finish this bounded reassessment.

## Evidence and limits

[Protocol](Protocol.md), [amendment](Amendment.md), [source reference controls](Reference.md), [V1 review](ReviewV1.md), [V2 review](ReviewV2.md), versioned receipts, all eight prompts/answers/returned-text ledgers, exact candidate patches and snapshot hashes preserve the findings. Reader accounting was qualified; original history and frozen input identities were rechecked unchanged. Missing linked raw historical qualification was disclosed instead of invented. Historical numeric results are report-attributed, not independently rerun here.

Two known retrospective tasks, one observation per condition and an adaptive correction cannot estimate population performance or run variability. Review was independent of the readers but used the same model environment and source-defined criteria. Preparation, research, writing and review effort were not metered; eight sessions are an experiment expense, not demonstrated net savings. [Reproduction notes](Reproduce.md) document input identities, setup errors and accounting limits. Mechanical validation supports preservation only; it does not establish map benefit.
