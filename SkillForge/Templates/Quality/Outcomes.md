# Outcomes template

Status: template, not a populated quality record.

Record: Stable criterion ID, desired outcome, observable check, requirement/preference/assumption type, source, rationale, and unresolved questions.

Where useful, include a parent outcome ID and a concrete failure/valid-alternative pair to explain the required granularity. Follow [EstablishQuality](../../Procedures/EstablishQuality.md#outcome-contribution-mapping) for contribution mapping; do not derive goals merely by copying the current component list.

| Outcome ID / parent | Specific result and contrasting examples | Contributor(s) and distinct contribution | Mapping rationale / gap / uncertainty |
|---|---|---|---|
| Populate only relevant relationships | Keep the link to the user's purpose | Existing or proposed; primary/shared only when helpful | Mark uncovered outcomes and unsupported design assumptions |

This optional map can use prose or existing records instead of a table. Keep shared requirements explicit. A contribution assignment is not causal evidence or permission to restructure, and overlapping mappings do not multiply a finding's score. For simple outcomes, omit unnecessary hierarchy and mapping.

Include scope, version/date, sources, unresolved questions, and revision triggers. Reuse existing authoritative records by link. Keep reserved tests outside routine skill context.
