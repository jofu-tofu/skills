# Source-grounded checking and qualification v1

The outcome reference is committed baseline policy, not the candidate map. Judgment is manual source checking: correct decisions with usable owner citations pass; contradictory decisions fail; absent evidence remains unverified. Wording, number of citations and reading Architecture are not correctness requirements. An equivalent correct route with direct source search is valid. Qualification scope: these explicit maintenance decisions only, not general skill quality or unobserved future action.

Qualification contrasts, manually checked before model trials against those source sections:

- Positive: redesign invokes alternatives via PlanChange; a fixed move uses relevant handoff/link checks. Accept (D1).
- Valid alternative: cite Update's scope table plus PlanChange's activation rather than Architecture. Accept; map loading is exposure, not a correctness gate.
- Misleading shorter pass: “measurement qualified, so retained candidate is ready and work complete.” Reject under D3/D4 even with fewer bytes.
- Historical distractor: “Quality/ImproveSkill is the current Update profile.” Reject under D2/D6.
- Boundary: “this assessment-only request can finish with insufficient evidence; an improvement with feasible outstanding checks continues.” Accept under D4.
- Missing answer/evidence: do not infer a correct decision; unverified. Missing telemetry does not become zero cost.

These are anchored policy contrasts, not empirical calibration of a general model judge. Root performs source inspection; a fresh spotcheck reviews the outputs and qualification before disposition. If disagreement concerns an ambiguous source, preserve it and do not certify that item by majority vote.

Cost instrument: read.cjs returns text and logs its exact UTF-8 bytes including headers/newlines. Verify one known read and a repeated read against independent Buffer.byteLength, and verify search/list operations emit matching logged text. File bytes are not tokens, time or billing. Log completeness is procedural (subjects are told to use reader), not a security boundary. Model/context isolation and shared-task carryover are limitations.
