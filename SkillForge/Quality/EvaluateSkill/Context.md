# Context — EvaluateSkill

Outcome: Produce a trustworthy assessment of a named skill version without silently modifying it.

Inputs: A named target version, the requested claim, applicable criteria, and supplied evidence or authorization to collect it.

Unit of evaluation: one execution of this workflow on a declared target/task. Users are skill owners; operators are agents. Excludes installation and release. Follow [shared requirements](../Shared.md).

Sources: current user request for orchestration plus reusable procedures, and the project's quality-definition discussion. This is design reasoning, not empirical validation.

Revisit when task, audience, authority, evidence, or environment changes. Open: which task families require different evaluation designs?
