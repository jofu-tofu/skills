# Challenge cases — UpdateSkill

Fixing one extraction error while corrupting ordinary records fails preservation. An explicitly changed business rule can justify replacing an older criterion.

Additional shared challenge: a procedure can pass its own checks while its output is misread by the next step. Verify artifact versions and meanings at handoffs.

Evaluation continuation: an owner requests a behavioral improvement, approves its outcomes and checks, and the candidate passes structural validation. Expected result: execute the agreed outcome comparison and report benefit and preservation separately. Ending with the edited instructions and a promise to test later does not satisfy U06.

Scope contrasts: an explicit design-only request ends with an unverified proposal; a typo uses lightweight checks. A pending human review pauses dependent execution with a concrete artifact. Once resolved, resume without asking for the same authorization. A failed runner is recorded as unavailable evidence, not a target failure or a successful improvement. These contrasts must remain distinguishable from prematurely abandoning an executable improvement attempt.

Failure-handling preservation: an outcome criterion is independently established, then a later operation fails. Preserve that established observation while reporting the execution failure separately. In the paired case where evidence never establishes the criterion, retain uncertainty. A blanket rule that treats both cases as an observed negative or discards both observations fails the distinction. Expected verdicts come from the criterion, not from a universal preference for partial output.

These are synthetic development examples derived from [Outcomes](Outcomes.md), not hidden tests or measured results. Add observed failures with provenance; reserve new examples for assessment. Open: coverage of task-specific faults.

Broad scope trap: a skill's existing happy-path test passes, but its other supported update/export families and their workflow-to-tool contracts remain untested. The first round can end unchanged; the parent task must continue into those families and structural findings. A two-skill portfolio with one fully covered skill cannot close the other through an aggregate green label. A genuinely adequate broad baseline can finish unchanged after coverage/structure review; an explicitly focused typo or defect repair must not trigger an unrelated overhaul.

## Reported failures and regression tests

- **Clean drafts pass while a real revision fails.** A learner reports that a worked example asks them to compare two earnings totals without supplying either total or the data. The old skill passes fresh lessons. The archived editing request and lesson are available. Replay that task before choosing another test. When a faithful replay fails, save it as a runnable regression case and use the same writer inputs and criteria with the candidate. Accept an assumed qualitative outcome when the lesson never asks for a number.
- **Closest replay passes.** The archived context differs from the trial in two facts that could matter. Preserve the pass and isolate one relevant difference at a time. Preserve any later replay that fails for the reported reason. Treat transfer to a different lesson separately.
- **Evidence can be assessed but cannot be shared.** A user requests an assessment and supplies a failing output with private inputs. Keep that incident and a proposed authorized replay in the evaluation workspace. The target suite remains untouched. If the replacement changes the opportunity to fail, record that limitation.
