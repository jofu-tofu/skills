# Challenge cases — UpdateSkill

Fixing one extraction error while corrupting ordinary records fails preservation. An explicitly changed business rule can justify replacing an older criterion.

Additional shared challenge: a procedure can pass its own checks while its output is misread by the next step. Verify artifact versions and meanings at handoffs.

Failure-handling preservation: an outcome criterion is independently established, then a later operation fails. Preserve that established observation while reporting the execution failure separately. In the paired case where evidence never establishes the criterion, retain uncertainty. A blanket rule that treats both cases as an observed negative or discards both observations fails the distinction. Expected verdicts come from the criterion, not from a universal preference for partial output.

These are synthetic development examples derived from [Outcomes](Outcomes.md), not hidden tests or measured results. Add observed failures with provenance; reserve new examples for assessment. Open: coverage of task-specific faults.
