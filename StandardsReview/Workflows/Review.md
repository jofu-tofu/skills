# StandardsReview Orchestrator

> You are a thin orchestrator. You spawn agents and check artifacts.
> You do NOT read workflow files yourself — agents read their own instructions.
> You do NOT write review findings — agents do that.

Read [ReviewContract](../Standards/ReviewContract.md) for shared artifact, scope and recovery rules. This is the interface contract, not a workflow implementation.

## Step 0: Resolve Paths

Set `SKILL_ROOT` to the directory containing the supplied StandardsReview SKILL.md. Resolve the reviewed repository/audit target independently. Pass absolute paths to agents and use the host's native filesystem and agent APIs.

## Path Conventions

`$REVIEW_DIR` follows the PAI context system convention:
  `_output/contexts/[context-slug]/reviews/standardsreview/[YYYYMMDD-HHMMSS]`

The `[context-slug]` is auto-generated by the PAI context hook (UserPromptSubmit) from the user's prompt text — the orchestrator does not derive it. It appears in the hook's output as `Context folder: [path]`. Use this path directly.

If no context hook output is available, create a task-local path labeled `YYYYMMDD-HHMM-standardsreview-[task-label]`; audits need no branch name.

## Step 1: Setup

Determine mode (diff/audit), preserve the exact target/range, exclusions and project constraints, then create the output directory using native filesystem tools. If a supplied context path is unavailable, choose and report a task-local output directory:

```bash
mkdir -p $REVIEW_DIR
```

## Step 2: Gather Context

Spawn agent:
- **prompt:** `"Read $SKILL_ROOT/Workflows/GatherContext.md and execute it. Mode: [diff/audit]. Repository/target root: [absolute path]. Target: [exact user range/path]. Preserve exclusions/project constraints: [values]. Write $REVIEW_DIR/context.md. Return ONLY its absolute path."`
- **subagent_type:** `general-purpose`

**CHECK:** Inspect `$REVIEW_DIR/context.md` existence and size; it must be nonempty. This metadata check does not require source-content interpretation.
- If missing -> retry once with same prompt.
- If missing again -> output error to user: "GatherContext failed after 2 attempts. Review aborted."

## Step 3: Select Dimensions

Spawn agent:
- **prompt:** `"Read $SKILL_ROOT/Workflows/SelectDimensions.md and execute it. Context file: $REVIEW_DIR/context.md. Dimensions directory: $SKILL_ROOT/Dimensions/. Write your output to: $REVIEW_DIR/dimensions.json. Return ONLY the absolute path to dimensions.json when done."`
- **subagent_type:** `general-purpose`

**CHECK:** Parse the object defined by ReviewContract; validate its `dimensions` array, required fields, existing rule paths and scoped file assignments.
- If missing/invalid, request correction once. If still invalid, report selection failure rather than dispatch guessed dimensions.

## Step 4: Spawn Review Agents

Read `$REVIEW_DIR/dimensions.json` — this is the ONLY artifact the orchestrator reads besides agent output file paths.

For EACH selected dimension, spawn a separate reviewer with the native agent API. Run within `agent_cap` and host capacity, queueing the rest; the cap does not erase coverage:
- **prompt:** `"Read $SKILL_ROOT/Standards/ReviewContract.md. Rules: [dimension.path] — apply the full dimension with project/version conditions. Context: $REVIEW_DIR/context.md. Files: [dimension.files]. Record actual files/rules examined, completion/partial/failure status, exclusions and supported findings. Include RULE_ID, severity, location, triggering condition, consequence, evidence and recommendation. Diff mode includes change-caused defects at unchanged lines exposed by deletions; distinguish unrelated pre-existing issues. Write $REVIEW_DIR/dimension-[dimension.id].md. Return ONLY its absolute path."`
- **subagent_type:** `general-purpose`

**SYNCHRONIZATION:** Store each agent's task_id and dimension id. After all spawned:
1. Wait with the native agent API for each task and collect its path
2. Check existence, nonempty output and status metadata. Retry a missing/invalid output once where feasible; preserve failed/missing IDs afterward
3. Reconcile available and failed/missing IDs against the manifest; path count alone is not complete coverage
4. Build the list of agent output paths for downstream steps

**The orchestrator does not interpret substantive findings.** It collects paths and checks status metadata; verification owns content interpretation.

## Step 5: Verify Claims and Generate Report

Spawn agent:
- **prompt:** `"Read $SKILL_ROOT/Workflows/VerifyAndReport.md and execute it. Available outputs: [paths]. Failed/missing dimensions: [IDs/reasons]. Context: $REVIEW_DIR/context.md. Manifest: $REVIEW_DIR/dimensions.json. Publication request: [explicit destination or none]. Write $REVIEW_DIR/verified-findings.md and $REVIEW_DIR/report.md. Return report content AND path. Preserve incomplete coverage even when available findings are verified."`
- **subagent_type:** `general-purpose`

**CHECK:** Both final artifacts exist and are nonempty. Retry the stage once if needed; otherwise report actual failure and preserve completed evidence.

Output the report to the user.
